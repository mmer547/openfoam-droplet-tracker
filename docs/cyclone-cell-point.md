# OpenFOAM v2606 の cellPoint 補間と定常 cyclone の粒子収支

このページは補間と外部面を合わせた第2段階の結果である。セル面ごとの積分を加えた比較は[最終検証](cyclone-parcel-tracking.md)を参照。

`--cell-point` を指定すると、v2606 が計算した節点速度・セル中心速度と、同じ四面体接続を使用する。定常 cyclone の保存座標9,396点を照合し、共通有効な9,390点で速度ベクトル差の最大は **6.06 × 10⁻¹⁵ m/s** だった。20 µm の投入停止後の出口流出は本コードで71個、v2606 で128個だった。同じ座標での速度補間が一致しても、軌跡と出口通過数には差が残る。

## 同じ座標での照合

WSL の OpenFOAM v2606（倍精度、ビルド `_481094f-20260618`）で、各座標に対する `mesh.findCell` と `cellPointWeight` の所属セル・面の3頂点・4個の重み、および `interpolationCellPoint<vector>` の速度を記録した。Python 側はこれらの正解列を使わず、63,877節点（33,058メッシュ点と30,819セル中心）、362,494四面体から独立に照会した。

| 照合項目 | 結果 |
|---|---:|
| 共通有効 / OpenFOAM のみ有効 / 本コードのみ有効 / 両者とも領域外判定 | 9,390 / 0 / 0 / 6 |
| 共通有効点での所属セル不一致 / 四面体不一致 | 0 / 0 |
| 重心座標の最大成分差 | 8.33 × 10⁻¹⁶ |
| 速度ベクトル差の中央値 / 95パーセンタイル / 最大（m/s） | 7.39 × 10⁻¹⁶ / 1.83 × 10⁻¹⁵ / 6.06 × 10⁻¹⁵ |

試作で速度差が 10⁻⁶ m/s 以上だった52点は、すべて VTK が許容差内とした隣の四面体に負の重みがあった。44点では同じセル内の別四面体、8点では別セルを選んでいた。修正版は候補の重心座標を検査し、必要に応じて周囲の候補を再探索する。52点の四面体はすべて一致し、速度差の最大は 1.99 × 10⁻¹⁵ m/s になった。

試作の最大差 0.01016 m/s は、座標 (−0.26689221, −0.40221928, 0.04436491) m で発生した。修正版と v2606 はともにセル10485と面頂点 (10841, 11566, 10842) を選び、セル中心と3頂点の重みは順に (0.70790230, 0.01061687, 0.00122890, 0.28025193) だった。

非定常場では前後の保存時刻に同じ空間重みを使って各速度を求め、時間方向に線形補間する。実ケースの試験用コピーに定常解と別の一様速度場を 0、0.5 s の2時刻として保存し、0.25 s の値を両端の v2606 直接評価の平均と照合した。共通9,390点で最大差は 3.31 × 10⁻¹⁵ m/s 以下だった。[補間実装](../cell_point.py)・[回帰試験](../tests/test_cell_point.py)

## 粒子収支

前段階と同じ定常 RANS 解、同じ1,024個の投入座標・順序・初速を使用した。投入は 0 ≤ t < 4 s に256個/s、終了は6 s、刻みは 1/4096 s。両コードで `sphereDrag`、浮力補正付き重力、完全付着壁を使用した。OpenFOAM の粒子数は同じ入力で保存済みの `icoUncoupledKinematicParcelFoam` の結果である。[条件・投入ファイルのハッシュと第1段階の結果](cyclone-cell-sampling.md)

| 粒径 | 計算 | 4 s 浮遊 | 4 s 累積流出 | 6 s 浮遊 | 6 s 壁付着 | 6 s 累積流出 | 6 s outside | 4～6 s 流出 |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| 20 µm | OpenFOAM v2606 | 585 | 87 | 291 | 518 | 215 | 0 | 128 |
| | 第1段階・VTK 節点補間 | 710 | 69 | 339 | 522 | 163 | 0 | 94 |
| | cellPoint・従来の VTK 外部面（切り分け用） | 501 | 59 | 197 | 462 | 130 | 235 | 71 |
| | **cellPoint・v2606 外部面（実装値）** | **584** | **59** | **301** | **593** | **130** | **0** | **71** |
| 100 µm | OpenFOAM v2606 | 26 | 0 | 0 | 1,024 | 0 | 0 | 0 |
| | 第1段階・VTK 節点補間 | 29 | 0 | 0 | 1,024 | 0 | 0 | 0 |
| | cellPoint・従来の VTK 外部面（切り分け用） | 26 | 0 | 0 | 1,021 | 0 | 3 | 0 |
| | **cellPoint・v2606 外部面（実装値）** | **26** | **0** | **0** | **1,024** | **0** | **0** | **0** |

入口逆流・その他境界終了は全計算で0個だった。全49時刻で投入数と各状態の合計が一致した。切り分け用計算で `outside` になった20 µm の235個、100 µm の3個は、v2606 の外部面を使うと同じIDがすべて壁付着になった。本コードでは `--cell-point` を指定したとき、入口の面積一様サンプリング、壁・出口との交差、速度補間で同じ四面体分割の外部面を使う。[0.125秒間隔の収支 CSV](cyclone-cell-point-counts.csv)

20 µm では6秒時の浮遊数の差は第1段階の48個から10個に縮まった。一方、停止後の流出不足は34個から57個に広がり、その時間帯に両者で流出した共通IDは60個から48個になった。現段階の本コードは各ステップ開始時の気体速度で粒子の移動と速度を更新する。次の改修では、セル面に達するまで移動し、その到達点で速度を更新する手順の影響を切り分ける。[改修プラン](cyclone-tracking-improvement-plan.md)

## 再現手順

WSL で v2606 の環境を読み込み、`wmake` でエクスポーターをビルドする。以下の `caseDir` は静止した再構築済みケースのディレクトリを指す。最初の2コマンドはリポジトリのルートから実行する。

```bash
source /usr/lib/openfoam/openfoam2606/etc/bashrc
wmake tools/exportCellPoint
exportCellPoint -case "$caseDir"
```

`postProcessing/trackerCellPoint` に倍精度座標、四面体の接続、境界三角形と各保存時刻の `U.dat` を出力する。追跡対象のケースで読み込む全保存時刻をエクスポートする。ケースや速度場を変更して再出力する場合は既存のエクスポートを別名に退避する。[エクスポーター](../tools/exportCellPoint/exportCellPoint.C)

Python 側は前段階の実行引数に `--cell-point` を加える。以下は定常 cyclone の20 µm の例である。

```bash
python track_particles.py frozen/cyclone.foam seeds.csv cellpoint-20.csv \
  --cell-point --diameter 1.9999999999999998e-5 --drag-model sphereDrag \
  --gas-density 1.2 --gas-viscosity 1.8816e-5 --liquid-density 1000 \
  --gravity 0 0 -9.81 --initial-velocity -10 0 0 --wall walls --outlet outlet \
  --start 0 --end 6 --dt 0.000244140625 --injection-duration 4 \
  --track-interval 0.125 --flow-csv cellpoint-rates-20.csv --flow-interval 0.125
```

局所速度も照合する場合は、初回の `exportCellPoint` に `-samplePoints /path/to/coordinates.dat` を加える。座標はヘッダーなし、各行が空白区切りの x y z（m）。同じ座標ファイルで次を実行すると、有効点・不一致の件数、重みと速度の誤差が得られる。

```bash
python tools/check_cell_point.py frozen/cyclone.foam coordinates.dat --time 0
python -m unittest discover -s tests -v
```
